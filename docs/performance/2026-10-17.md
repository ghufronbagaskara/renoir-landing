# Katalhys performance audit - 17 October 2026

The owner requested a code swarm to reduce loading and animation cost while preserving the approved visual identity. Three parallel audits covered client runtime, media delivery, and rendering/CSS. Subsequent feedback also requested a redesigned Home Problem section and clearer Notes cards.

No dependencies, framework islands, text entrances or perpetual animations were added. Existing GSAP/Swiper packages were not removed merely to reduce installation size: the measured Home runtime does not request them. A broad Latin font subset experiment saved only about 8% and was rejected to avoid adding another font pipeline.

## Design changes and verification

The Home Problem uses one static source-to-workflow composition: chat/spreadsheet/document questions, status/owner/next action, three scoped AI tasks and human review. A visible illustration label and separate real-project link distinguish the offer from shipped Work. It adds no client script. [Research and sources](../design/problem-refresh/research.md).

Home Notes uses tinted article bodies, white diagram panels and the existing localized cobalt button. Image, title and button lead to the same article. Original copy, diagrams and rail controls remain.

- Astro type check: 158 files, zero errors/warnings, five pre-existing hints.
- Unit tests: 10 passed. Internal links and privacy/copy checks: 45 built pages passed.
- Home refresh: 15 scenarios passed, including phone/desktop, reduced motion, save-data, no JavaScript and video failure.
- Motion: 26 scenarios passed, including stable headings, finite drawing and reduced-motion/no-JS fallbacks.
- Runtime: eight timing/selection/loading scenarios and three responsive/visibility scenarios passed.
- Focused design QA: 10 EN/ID scenarios at 1992, 1440, 412 and 320px, including actual image/button article navigation, reduced motion and no JavaScript. No horizontal overflow or page errors.
- Feedback regression: EN/ID ring drag, hover, four-second rotation/pause, crossfades, FAQ/engagement behavior, Pagefind/catalog search and inner navigation passed. Reduced-motion selection also passed.

The autoplay regression measures its deadline inside the page to avoid counting Playwright command overhead as part of the four-second interval. The offscreen case explicitly scrolls Work out of view before observing it.

## Measurement method

Lighthouse 12.8.2, real Chrome on Windows, production build served by the existing static server. Mobile simulation uses 150ms RTT, about 1.6Mbps throughput and 4x CPU slowdown. Baseline has one run per route. Final Home samples are repeated separately after functional browser suites finish. Raw JSON is retained in ignored `.work-capture/performance/`.

These are local lab samples, not deployed Core Web Vitals or real-device battery measurements. Baseline and final series happened at different times on the same host. Treat byte counts and instrumented callback/write reductions as stronger evidence than small score changes.

Home transfer is about 59% lower. The >=95 Home performance target remains unmet: all six final samples scored 92. TBT stays below 100ms and CLS is zero in these samples; baseline Home TBT was already zero, so the result is not a TBT improvement over that baseline. The removed startup forced layout had caused an intermediate regression and is absent in the final audit.

The remaining Home LCP element is the hero body paragraph, with roughly 2.34s of observed render delay in the first ID sample. Style/layout dominates that trace (about 1.68s). The lab score and Speed Index remain sensitive to the full-page first render and playing background video. These observations do not prove a remaining single-code-line cause; no arbitrary playback delay, hidden content, font replacement or guessed section heights were introduced to force the score.


## Reproduction

```powershell
bun run check
bun test

bun run serve
bun run check:links
bun run check:copy
node scripts/check-home-refresh.mjs
node scripts/check-home-feedback.mjs
node scripts/check-motion.mjs
```

The audit reused a cached Lighthouse CLI; no project dependency was installed. Ignored audit scripts include `run-lighthouse.mjs`, `release-home-lighthouse.mjs`, `measure-runtime.mjs`, `check-runtime.mjs`, `check-responsive-runtime.mjs`, `media-delivery.mjs` and `service-media-delivery.mjs`. Design checks and screenshots are in `.work-capture/problem-refresh/`.

No deployment, commit, publishing, source database change or screenshot-logo redaction was performed. Safari/iOS decoding, low-end physical devices, field INP and deployed cache/contact behavior were not measured.
